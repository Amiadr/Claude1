# יומן רעש לילי – תיעוד רעש משכנים עם חותמת זמן

כלים לבניית תיק ראיות על רעש חוזר בלילה (דפיקות על קיר, גרירת רהיטים, הפלות), בלי לשבת שעות על הקלטה של לילה שלם.

הרעיון בשני הכלים זהה: מודדים את רמת הקול כל הזמן, ושומרים **רק** את הקטעים שבהם הרמה עוברת סף, עם כמה שניות לפני ואחרי. לכל קטע נרשמים תאריך ושעה מדויקים, משך ורמת שיא, ומתקבל קובץ CSV מסודר ותיקיית קליפים.

| כלי | מתי משתמשים | איפה |
|---|---|---|
| **אפליקציית ווב "יומן רעש לילי"** | ניטור חי כל הלילה מהטלפון או מהמחשב, בלי התקנה. כולל ייבוא של הקלטה קיימת (M4A/MP3/WAV) וסריקתה באותו אופן | `docs/` |
| **`noise_events.py`** | אותה סריקה של הקלטה קיימת, אבל במחשב ובשורת הפקודה (גם לפורמטים שהדפדפן לא מפענח, כמו AMR/3GP) | `tools/` |

---

## 1. אפליקציית הווב (`docs/`)

דף אינטרנט אחד שרץ בדפדפן. אין שרת ואין העלאה לענן: ההקלטות נשמרות במכשיר בלבד (IndexedDB) ומיוצאות כ-ZIP.

**מה היא עושה**
- מאזינה למיקרופון עם עיבוד כבוי (ללא ביטול הד, ללא סינון רעשים, ללא AGC) כדי שדפיקות עמומות לא יימחקו.
- מציגה מד רמה חי וקו סף. כל חריגה מהסף פותחת אירוע: X שניות מהזיכרון לפני הרעש, הרעש עצמו, ו-Y שניות שקט אחריו.
- לכל אירוע: תאריך, שעה מדויקת (עד אלפית שנייה ב-CSV), משך, רמת שיא וממוצע, שדה הערה (למשל "דפיקות"), ניגון, הורדה ומחיקה.
- קיבוץ לפי לילה (מ-12:00 בצהריים עד 12:00 למחרת), ייצוא CSV או ZIP עם כל הקליפים + CSV + יומן פעולות.
- יומן פעולות שמתעד מתי הניטור התחיל ונעצר, ואזהרות על פערים (מסך שעבר לרקע, מיקרופון שנותק). זה מה שמראה שהניטור היה רציף.
- "מסך לילה": מסך שחור עם שעון, הניטור ממשיך. ניסיון להשאיר את המסך דלוק (Wake Lock).
- חותמות הזמן מחושבות משעון האודיו, לא מזמן העיבוד, ולכן מדויקות גם אם הדפדפן מאט את הדף ברקע.
- ניתנת להתקנה כאפליקציה (PWA) ועובדת גם בלי אינטרנט אחרי הטעינה הראשונה.

**הפעלה**

הדפדפן דורש HTTPS (או localhost) כדי לפתוח מיקרופון. שתי דרכים:

1. **אירוח סטטי חינמי (מומלץ לטלפון).** ה-`docs/` היא תיקייה סטטית, וכל שירות אירוח סטטי מגיש אותה ב-HTTPS:
   - **GitHub Pages** (הכי פשוט למאגר ציבורי, בלי חשבון נוסף): Settings → Pages → Source: *Deploy from a branch* → Branch `main`, Folder `/docs` → Save. אחרי כדקה הדף זמין ב-`https://<user>.github.io/<repo>/`, ומתעדכן בכל push ל-`main`. למאגר פרטי זה דורש GitHub Pro, ואז עדיף אחת מהאפשרויות הבאות.
   - **Cloudflare Pages** (חינם, עובד גם עם מאגר פרטי): ב-[dash.cloudflare.com](https://dash.cloudflare.com) → Workers & Pages → Create → Pages → Connect to Git → בוחרים את המאגר → Build command ריק, Build output directory: `docs` → Save and Deploy. הכתובת: `https://<שם>.pages.dev`.
   - **Netlify** (חינם, גם מאגר פרטי): Add new site → Import an existing project → GitHub → המאגר → Publish directory: `docs` → Deploy. הכתובת: `https://<שם>.netlify.app`. בלי Git בכלל: Netlify Drop, גוררים את התיקייה `docs` לדפדפן ומקבלים כתובת (ואז מעלים שוב ידנית בכל עדכון).
   במאגר אין שום דבר רגיש: ההקלטות נשארות במכשיר וב-Drive שלכם, וה-Client ID של גוגל הוא מזהה ציבורי שעובד רק מהכתובות שרשמתם.
   בכל המקרים: פותחים את הכתובת בטלפון, ובתפריט הדפדפן "הוסף למסך הבית". את אותה כתובת רושמים ב-Google Cloud כ-Authorized JavaScript origin (ראו סעיף Drive).
2. **מחשב נייד (הכי אמין לניטור לילי).** `cd docs && python3 -m http.server 8000` ואז `http://localhost:8000` ב-Chrome. מחשב מחובר לחשמל עם כיבוי שינה אוטומטית לא "נרדם" ולא נחנק על ידי חיסכון בסוללה כמו טלפון. `localhost` נחשב מאובטח, אז המיקרופון עובד, וגם `http://localhost:8000` אפשר לרשום בגוגל.
3. **בטלפון בלי שרת בכלל (אנדרואיד):** מתקינים את Termux, מעתיקים את תיקיית `docs` לטלפון, ומריצים בה `python -m http.server 8000`. אז `http://localhost:8000` ב-Chrome של הטלפון עובד כמו אתר HTTPS, גם בלי אינטרנט. מתאים למי שנוח לו עם טרמינל.

**טיפים לשימוש**
- להניח את המכשיר קרוב לקיר או לרצפה שמהם מגיע הרעש, מחובר למטען.
- ללחוץ "התחל ניטור", לחכות לשקט, וללחוץ "כיול אוטומטי". הסף נקבע 8 יחידות מעל רמת הרקע (דפיקות שקטות דרך הקיר הן לעיתים רק 8 עד 13 מעליה). אם יש התראות שווא, להעלות; אם מפספס, להוריד.
- אנדרואיד: בהגדרות האפליקציה של Chrome לבטל "אופטימיזציית סוללה", ולהשאיר את הדף בחזית עם "מסך לילה".
- אייפון: Safari עוצר הקלטה כשהמסך ננעל. חובה להשאיר מסך דלוק (ההגדרה "השאר מסך דלוק" עובדת מ-Safari 16.4).
- בבוקר: לייצא ZIP ולשמור עותק במחשב או בענן. מחיקת נתוני האתר בדפדפן מוחקת גם את ההקלטות.
- הרמות הן בסולם יחסי (dBFS + 100) ולא dB(A) מכויל. לצורך ראיה החשוב הוא ההקלטה, השעה והיומן הרציף.

**ייבוא הקלטה קיימת (בתוך האפליקציה)**

יש כבר הקלטה של לילה שלם מאפליקציית רשמקול? בכרטיס "ייבוא הקלטה קיימת" בוחרים את הקובץ, והאפליקציה:
1. מזהה את הפורמט וקוראת מהקובץ את זמן ההתחלה: תאריך היצירה במטא-דאטה של MP4/M4A (mvhd או ©day), תאריך בשם הקובץ (למשל `2026-09-26 23-10-05.m4a` או `20260926_231005.mp3`), או זמן השינוי של הקובץ פחות אורך ההקלטה. כל המועמדים מוצגים כצ'יפים. אם זמן היצירה במטא-דאטה נראה כמו זמן *סיום* ההקלטה (קרוב לזמן השינוי של הקובץ), מוצעת גם האפשרות "פחות אורך ההקלטה".
   **קביעת הזמן ידנית:** בוררי תאריך ושעה (עם שניות), ובחירה אם הזמן שהוזן הוא *תחילת* ההקלטה או *סיומה* (ואז האורך מחוסר אוטומטית). זה חשוב כשממירים קובץ לפורמט אחר: המטא-דאטה וזמן הקובץ של הקובץ המומר לא נכונים, ומקלידים את הזמן מההקלטה המקורית. אם שומרים את השם המקורי של הקובץ, הזמן נקרא ממנו. מתחת לבוררים מוצג טווח ההקלטה המחושב לבדיקה.
   **תיקון אחרי שמירה:** בתחתית כרטיס הייבוא, "תיקון זמן של ייבוא שכבר נשמר": בוחרים את הייבוא, מזינים את הזמן הנכון (התחלה או סיום), וכל האירועים שלו מוזזים יחד. הזמן המקורי נשמר (תג "זמן תוקן"), יומן הסריקות מתעדכן, ושמות הקבצים והתיקיות ב-Drive מתעדכנים בסנכרון הבא, גם אם התיקון מעביר אותם לחודש אחר.
2. סורקת את הקובץ בזרימה ב-Web Worker: WAV נקרא ישירות, M4A/AAC ו-MP3 מפוענחים דרך WebCodecs. הקובץ לא נטען כולו לזיכרון, ולכן הקלטה של 8 שעות עוברת גם בטלפון (בדרך כלל תוך דקה או שתיים). פורמטים אחרים (OGG/Opus, WebM, FLAC) מפוענחים כולם בזיכרון, מתאים להקלטות של עד כשעה. AMR/3GP לא נתמך בדפדפן, לזה יש את הכלי הפייתוני.
3. מציגה ציר זמן של רמת הרעש לכל הלילה עם קו הסף, ומאפשרת להזיז את הסף ולראות מיד כמה אירועים נמצאים (בלי לסרוק שוב). הסף המוצע: רמת הרקע (חציון) + 8. דפיקות שקטות דרך הקיר הן לעיתים רק 8 עד 13 מעל הרקע; אם נכנסים יותר מדי רעשי רקע, מעלים את הסף.
4. "האזנה ובחירה" מסווגת כל אירוע אוטומטית (דפיקה / רעש רציף / ייתכן דיבור), מאחדת רעשים צמודים לאירוע אחד, ומציגה רשימה: לכל אירוע שעה, משך, רמה, תג הסיווג (עם מבנה הרעש: כמה דפיקות, כמה רעש רציף), נגן שמראה את צורת הרעש ותיבת סימון. מסמנים רק מה שרלוונטי. יש כפתור שמבטל בלחיצה אחת את הסימון של כל מה שנשמע כדיבור.
5. "שמור" מחלץ מהקובץ רק את האירועים המסומנים, ושומר אותם ברשימת האירועים הרגילה עם תג "מקובץ", השעה המדויקת (זמן התחלה + היסט בקובץ), וההיסט בהקלטה המקורית (כדי שאפשר יהיה לאמת מול הקובץ המקורי). הכל מיוצא ב-CSV וב-ZIP כרגיל. מה שלא סומן לא נשמר בשום מקום; היומן רושם רק כמה אירועים הוסרו בסקירה.

**מגבלות ידועות**
- ייבוא M4A/AAC דורש דפדפן עם פענוח AAC ב-WebCodecs: Chrome/Edge 94+ (גם באנדרואיד), Safari 17+. Chromium "נקי" (למשל זה של Playwright) בלי קודקים קנייניים לא יפענח AAC, וזה מה שהבדיקה האוטומטית כאן רואה.
- דפדפן בטלפון הוא לא שירות רקע. אם המערכת הורגת את הדפדפן, הניטור נעצר (וזה יופיע ביומן כפער). בשביל אמינות מלאה בטלפון צריך אפליקציה נייטיבית עם foreground service; זה השלב הבא אם הגישה הזו לא מספיקה.
- 16 kHz מונו: מספיק לדפיקות וגרירות (עד 8 kHz), וחוסך מקום (כ-2 MB לדקת הקלטה). אפשר לעבור ל-48 kHz בהגדרות.

**פרטיות: מה נשמר ומה לא**

- האפליקציה לא מקליטה ברצף. בזיכרון נשמרות רק השניות האחרונות (ה-pre-roll), וברגע שהרמה יורדת מתחת לסף, מה שלא נכנס לאירוע נזרק. שיחה שקטה מתחת לסף לא נקלטת בכלל. לכן חשוב לכייל את הסף מעל רמת הדיבור הרגילה במקום שבו מונח המכשיר (הכפתור "כיול אוטומטי", ואפשר להעלות עוד).
- כל אירוע מסווג אוטומטית (ראו "איך הסיווג עובד" למטה): **דפיקה**, **דפיקה + גרירה**, **רעש רציף**, **נשימה** או **ייתכן דיבור**. זה רמז לסקירה, לא זיהוי ודאי: מוזיקה או טלוויזיה ייראו כדיבור, ודיבור לחוש או צעקה קצרה עלולים להתפספס.
- **בייבוא קובץ** שום דבר לא נשמר עד שעוברים על הרשימה ומסמנים. אירועים שלא סומנו לא נשמרים.
- **בניטור חי** אין מי שיסקור בזמן אמת, ולכן יש שתי אפשרויות: (א) ברירת המחדל: הכל מעל הסף נשמר, אירועים דמויי דיבור מקבלים תג, ובבוקר מסמנים אותם בלחיצה אחת ("סמן את כל 'ייתכן דיבור'"), מאזינים ומוחקים. (ב) ההגדרה "סינון דיבור": אירועים שנשמעים כדיבור לא נשמרים בכלל. ביומן נרשם רק בסוף המפגש כמה אירועים סוננו, בלי שעות.
- יומן הפעולות לא מכיל תוכן אודיו, רק שעות, רמות ומשכים. מחיקה ידנית נרשמת ביומן כ"הוסרו בסקירה" עם הכמות בלבד. הכל נשאר במכשיר עד שמייצאים.
- מומלץ להאזין לכל קליפ לפני שמצרפים אותו לתיק, גם כדי לוודא שאין בו שיחה שלכם ברקע.

**Google Drive: גיבוי, שיתוף בין מכשירים ויומן סריקות**

בכרטיס "Google Drive" מתחברים לחשבון גוגל, ומאז כל לחיצה על "סנכרן עכשיו":
- מעלה את הקליפים שנשמרו (אחרי סקירה) ועדיין לא הועלו, לתיקייה `יומן רעש/<שנה>/<שנה-חודש>/`. שם כל קובץ כולל את התאריך, השעה, שם המכשיר ומזהה קצר, למשל `2026-09-26_23-41-07_טלפון_ab326d.wav`. שם המכשיר נקבע בכרטיס ונשמר גם במטא-דאטה של הקובץ.
- מעדכן בכל תיקיית חודש קובץ `events-<חודש>.json` (אינדקס משותף לכל המכשירים) ו-`events-<חודש>.csv` עם כל האירועים של החודש מכל המכשירים, כולל עמודת "מכשיר".
- מוריד לרשימה המקומית אירועים שהועלו ממכשירים אחרים (תג "מ-Drive · שם המכשיר"). הקליפ עצמו יורד רק כשמנגנים, מורידים או מייצאים ZIP, ואז נשמר גם מקומית.
- ממזג את `scan-log.json`, יומן הסריקות המשותף: אילו קבצים ואילו טווחי זמן כבר נסרקו, באיזה מכשיר, מתי וכמה אירועים נשמרו. גם מפגשי ניטור חי נרשמים בו.

לפני סריקה של קובץ, האפליקציה בודקת ביומן הסריקות (ומרעננת אותו מ-Drive אם מחוברים). אם הקובץ עצמו כבר נסרק, או שטווח הזמן שלו חופף לסריקה קודמת או לניטור חי, מוצגת הודעה עם הפרטים ושאלה אם לסרוק בכל זאת. סריקה חוזרת מוסיפה את האירועים לצד הקיימים.

מחיקה של אירוע שהועלה שואלת אם למחוק גם מ-Drive. מחיקה מ-Drive מסירה אותו גם מהאינדקס, ובסנכרון הבא הוא נעלם גם במכשירים האחרים. מחיקה "רק מהמכשיר הזה" משאירה את הקובץ ב-Drive והאירוע לא יחזור לרשימה בסנכרון.

*הגדרת הגישה לגוגל (פעם אחת, כעשר דקות):*
1. ב-[Google Cloud Console](https://console.cloud.google.com/) יוצרים פרויקט חדש (השם לא משנה).
2. APIs & Services → Library → מחפשים "Google Drive API" → Enable.
3. APIs & Services → OAuth consent screen → User type: External → ממלאים שם לאפליקציה ואימייל → ב-Test users מוסיפים את כתובת הג'ימייל שלכם (ושל כל מי שישתמש). האפליקציה נשארת במצב Testing; אין צורך באימות של גוגל.
4. APIs & Services → Credentials → Create credentials → OAuth client ID → Application type: Web application. ב-Authorized JavaScript origins מוסיפים את כתובת האתר כפי שהיא מוגשת, למשל `https://<user>.github.io` או `https://noise-log.pages.dev` (רק הדומיין, בלי נתיב אחריו), וגם `http://localhost:8000` אם מריצים במחשב או ב-Termux. Authorized redirect URIs נשאר ריק.
5. מעתיקים את ה-Client ID (מסתיים ב-`.apps.googleusercontent.com`) לשדה בכרטיס Google Drive באפליקציה, או ל-`docs/config.js` כדי שיהיה בכל המכשירים.

ההרשאה שמתבקשת היא `drive.file`: האפליקציה רואה ויכולה לשנות רק קבצים שהיא עצמה יצרה. הטוקן תקף לשעה ומתחדש בשקט כשהחשבון מחובר בדפדפן; אם ההתחדשות נכשלת, לוחצים "התחבר" שוב. שום דבר לא עובר דרך שרת של האפליקציה, הכל ישירות בין הדפדפן ל-Google.

מגבלות: הסנכרון ידני בלבד. שני מכשירים שמסנכרנים בדיוק באותו רגע עלולים לדרוס זה את האינדקס של זה, אבל הסנכרון הבא של כל מכשיר משלים את החסר מהרשימה המקומית שלו. שכבת ה-Drive נבדקה מול הדמיה מקומית של ה-API (`tests/mock-drive.js`), לא מול גוגל.

**סינון רעשי רקע ונשימות**

כשהמכשיר ליד המיטה, רוב האירועים בלילה הם נשימות. שלוש שכבות מטפלות בזה:

1. **זיהוי לפי תדרים נמוכים בלבד.** דפיקות על קיר וגרירת רהיטים עוברות דרך הבניין בעיקר מתחת ל-300 Hz; נשימות, איוושות ורוב רעשי הרקע כמעט ולא. בהגדרות: "זיהוי לפי תדרים נמוכים בלבד" (חל על הניטור החי ועל ברירת המחדל בייבוא), ובתוצאות הייבוא אפשר להחליף בין "כל התדרים" ל"תדרים נמוכים" ולראות מיד את ההבדל בציר הזמן ובמספר האירועים. זו השכבה היעילה ביותר: נשימות לא נכנסות בכלל.
2. **סיווג ורעש מחזורי.** אירועים שנשמעים כנשימה מקבלים תג "נשימה". בנוסף, רצף של 6 אירועים ומעלה במרווחים קבועים (1.5 עד 8 שניות, כמו קצב נשימה) מסומן כרעש מחזורי ומקבל "נשימה?" גם אם הצליל עצמו לא זוהה. בסקירה: "בטל סימון נשימות" בלחיצה אחת. בניטור חי: "סינון נשימות" בהגדרות לא שומר אותם בכלל.
3. **מסננים ומיון בסקירה וברשימה.** צ'יפים לפי סוג (לחיצה מסתירה/מציגה, עם ספירה), רמת שיא מינימלית, מיון "החזקים קודם", ו"סמן/בטל סימון של המוצגים". ברשימת האירועים השמורים: אותם צ'יפים, מיון, ו"סמן את כל המוצגים" למחיקה קבוצתית. הייצוא מכבד את הסינון הנוכחי.

**איך הסיווג עובד**

המסווג לא "מבין" צלילים; הוא מסתכל על מבנה הרעש בזמן, לא על עוצמתו:
- נמדדת מעטפת הרמה של הקליפ כל 10 אלפיות שנייה, בדציבלים מעל רקע הקליפ (הקליפ כולל שקט לפני הרעש ואחריו). מה שמתחת ל-6 dB מעל הרקע נחשב רקע ולא נספר, בלי קשר לעוצמה המוחלטת. כך דפיקה שקטה ליד כיסא רועש נמדדת בנפרד ולא נבלעת.
- **דפיקה**: שיא בולט (8 dB ומעלה מעל הרקע, 6 dB ומעלה מעל מה שלפניו) שעולה מהר (עד 100 אלפיות שנייה מחצי הגובה לשיא) ונעלם מהר (200 אלפיות שנייה אחרי השיא הרמה נמוכה ב-5 dB ומעלה). כל דפיקה נספרת ("5 דפיקות"). כיסא שנטרק ומקפץ הוא דפיקה; אם הוא נגרר אחר כך, זה "דפיקה + גרירה".
- **רעש רציף**: רמה מוגבהת שנמשכת חצי שנייה ומעלה ואינה זנב של דפיקה (גרירה, מנוע, מכונית שעוברת, רקע שעולה לאט). **נשימה**: רעש רציף בצורת גבעה (עלייה איטית, 150 אלפיות שנייה ומעלה, ודעיכה איטית), 0.3 עד 4 שניות, איוושה בתדרים גבוהים כמעט בלי תדרים נמוכים, לא קולית. **דפיקה + גרירה**: קליפ עם דפיקות וגם רעש רציף. **ייתכן דיבור**: מחזוריות עם גובה צליל משתנה וקצב הברות, נמדד על כל הקליפ.
- הסיווג נבדק על אותות סינתטיים ועל הקלטה אמיתית של דפיקות שקטות וכיסא. על הקלטות אחרות ייתכנו טעויות, ולכן הוא תמיד מלווה בהאזנה ובבחירה ידנית.
- **הנגן** מראה את מעטפת הקליפ (אותה מעטפת שהמסווג מודד), עם המקטעים שסווגו צבועים על הגרף (כתום: דפיקה, סגול: רעש רציף, אפור: נשימה) וקו מקווקו בתחילת הרעש. הסמן זז על הצורה בזמן הניגון, ולחיצה על הגרף מדלגת.

**איחוד רעשים צמודים לאירוע אחד**

הזיהוי סוגר אירוע אחרי "שקט לסיום אירוע" (הזנב), ואירוע חדש מתחיל עם "שניות לפני הרעש" (ה-pre-roll). כשהרעש הבא מגיע לפני שנגמרו הזנב וה-pre-roll של הקודם (בברירת המחדל: פחות מ-6 שניות אחרי הרעש הקודם), הקליפים צמודים והם בעצם אפיזודה אחת: סדרת דפיקות, דפיקה ואז גרירה, דפיקות ואז כיסא שנטרק. אחרי הסיווג הם מאוחדים לאירוע אחד (תג "אוחד מ-N"), בייבוא ובניטור חי כאחד. לא מאוחדים: נשימות, דיבור ורעש מחזורי (שם ההפרדה בין האירועים היא המידע), וגם לא מעבר ל"אורך קליפ מרבי". כדי לאחד רעשים רחוקים יותר זה מזה, מגדילים את "שקט לסיום אירוע" או את "שניות לפני הרעש". הכלי הפייתוני (`tools/noise_events.py`) לא מסווג ולכן לא מאחד; שם עוזר `--tail` גדול יותר.

## 2. חילוץ אירועים מהקלטה קיימת (`tools/noise_events.py`)

לוקח הקלטה ארוכה (WAV ישירות, או m4a/mp3/ogg דרך ffmpeg), מוצא את הקטעים הרועשים, וכותב:
- `clips/2026-09-26_23-41-07_ev003.wav` – קליפ לכל אירוע, שם הקובץ הוא התאריך והשעה של תחילת הרעש
- `events.csv` – טבלה: תאריך, שעה, משך, רמה, והיסט בתוך ההקלטה המקורית (כדי למצוא את המקום גם בקובץ המקורי)
- `summary.txt` – סיכום קריא

```bash
pip install numpy            # פעם אחת
python3 tools/noise_events.py night.m4a --start "2026-09-26 23:10"
python3 tools/noise_events.py night.wav --start "2026-09-26 23:10" --threshold -40 --pre 3 --tail 3
python3 tools/noise_events.py night.mp3 --no-clips     # רק לראות את הרשימה
```

- `--start` הוא זמן תחילת ההקלטה (אפליקציות רשמקול בדרך כלל שמות אותו בשם הקובץ; הכלי מנסה לקרוא אותו משם הקובץ אם לא ניתן).
- בלי `--threshold` הסף נקבע אוטומטית: רמת הרקע (חציון) + 8 dB. `--margin` משנה את המרווח (להעלות אם נכנסים יותר מדי רעשי רקע).
- `--min-ms 100` מסנן קליקים קצרצרים. `--max-clip` מפצל רעש ארוך לכמה קליפים.
- קבצים שאינם WAV דורשים `ffmpeg` בנתיב (או `--ffmpeg /path/to/ffmpeg`).

## 3. פתרונות קיימים (לפני שבונים)

- **Noise Log – Neighbor Complaint** (אנדרואיד ו-iOS): מד דציבלים, הקלטה ברקע, אירוע אוטומטי עם תאריך, שעה ורמת שיא כשעוברים סף. הכי קרוב לדרישה.
- **Nuisance Noise Recorder** (אנדרואיד): קטעים של 30 שניות בכל חריגה מסף, שם קובץ עם שעה, ייצוא ZIP + CSV לפי תאריך.
- **Voice Activated Recorder** (אנדרואיד): רשמקול שמדלג על שקט אבל שומר את הזמן המקורי של כל קטע.
- **Sleep as Android** (אנדרואיד): "הקלטת רעשי שינה" שומרת קטעים מעל סף עם שעה, ומציגה גרף רעש של כל הלילה. מיועדת לנחירות, אבל עושה בדיוק את זה.
- **מצלמת אבטחה ביתית עם זיהוי קול** (Eufy Indoor, Tapo, Wyze): קליפ מתוזמן עם חותמת זמן צרובה בווידאו בכל רעש. ב-Eufy/Tapo נשמר לכרטיס SD בלי מנוי; ב-Wyze זיהוי קול דורש מנוי Cam Plus.
- **The Noise App** (RHE Global): מקובל כראיה בבתי משפט בבריטניה, אבל בנוי לשליחה לרשויות מקומיות בריטיות.
- **Sound Notifications באנדרואיד / Sound Recognition באייפון** (הגדרות נגישות): מזהים "דפיקה בדלת" ושומרים ציר זמן של זיהויים, בלי הקלטה. תיעוד משלים וזול.
- **מחשב נייד עם sox**: `rec -c 1 out.wav silence 1 0.1 3% 1 3.0 3%` בלולאה עם שם קובץ לפי שעה. עובד, אבל בלי ממשק.

## 4. תיק הראיות (לא ייעוץ משפטי)

- **יומן רעש כתוב** לצד ההקלטות: תאריך, שעה, סוג הרעש, משך, מי שמע, איך זה השפיע. ה-CSV מהכלים כאן הוא בסיס טוב, ושדה ההערה נועד בדיוק לזה.
- לשמור את הקבצים המקוריים בלי עריכה, ולהעלות מיד לענן או לשלוח לעצמכם במייל. חותמת ההעלאה מחזקת את האותנטיות.
- תלונה בכתב לשכן ולוועד הבית, פנייה למוקד העירוני (106) ולמשטרה בזמן אמת (100) בזמן הרעש. תיעוד הפניות הוא חלק מהתיק.
- תקנות למניעת מפגעים (רעש בלתי סביר) מגדירות שעות מנוחה, בהן 23:00 עד 07:00. רעש מכוון וחוזר בשעות אלה הוא הבסיס לתביעת מטרד, לרוב בבית משפט לתביעות קטנות.
- להקליט רעש שחודר לדירה שלכם זה בדרך כלל בסדר; להקליט שיחות של השכנים לא. הכלים כאן שומרים רק קטעים קצרים מעל סף, אבל כדאי להיוועץ בעורך דין לפני הגשת תביעה.
